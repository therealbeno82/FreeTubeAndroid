# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

FreeTube Android is a fork of [FreeTube](https://github.com/FreeTubeApp/FreeTube) that adds an
Android target. One Vue 3 renderer in `src/renderer/` is shared by **three build targets**:

| Target | Shell | Data backends |
| --- | --- | --- |
| Android APK | Kotlin `WebView` in `android/` | local extractor (youtubei.js) + Invidious |
| Electron desktop | `src/main/` | local extractor (youtubei.js) + Invidious |
| PWA / web | static site, Docker image | Invidious only |

Almost all feature work happens in `src/renderer/` and applies to every target at once.

## Package manager

The project is pnpm (`pnpm-lock.yaml`, `pnpm-workspace.yaml`), and CI uses pnpm. The README's
build section still says `yarn` — that is stale, ignore it.

pnpm is **not on PATH on this machine**. Corepack provides it:

```bash
"C:/Program Files/nodejs/corepack" pnpm install
```

Every `pnpm run <script>` below can equivalently be run through corepack, or by invoking the
underlying `webpack`/`eslint` command with `npx` (see `package.json` for the exact expansion).

## Commands

```bash
pnpm run lint
```

`lint` = eslint + stylelint. `lint-all` adds JSON. `lint-fix` autofixes. There is **no test suite**.

Development:

```bash
pnpm run dev
```

`dev` runs Electron, `dev:web` runs the PWA, `debug` runs Electron with remote debugging.
There is no watch-mode dev server for the Android target — rebuild the assets and reinstall.

Packing (writes bundles; does not produce an installable app on its own):

```bash
pnpm run pack:android
```

`pack:android` = botguard script + production renderer, both emitted into
`android/app/src/main/assets/`. `pack:android:dev` is the development-mode variant CI uses for
nightlies. `pack` targets Electron, `pack:web` targets the PWA.

### Building the APK

Two stages: webpack writes the web assets into the Gradle project, then Gradle builds the APK.

```bash
pnpm run pack:android
```

```bash
cd android && JAVA_HOME="C:/Program Files/Java/jdk-17" ANDROID_HOME="$LOCALAPPDATA/Android/Sdk" ./gradlew assembleDebug
```

Output: `android/app/build/outputs/apk/debug/app-debug.apk`.

**The Gradle wrapper is 8.2, which does not support Java 23** — the JDK on this machine's PATH.
The build fails unless `JAVA_HOME` points at JDK 17 (matching `.github/workflows/buildCordova.yml`).
`ANDROID_HOME` is also unset in the shell and there is no `android/local.properties`, so it must be
passed too.

`android/app/src/main/assets/` is gitignored and fully regenerated by the pack step. Webpack does
not clean it, so switching between dev and production mode can leave an orphaned hashed CSS file
behind; the regenerated `index.html` names the current one.

Desktop releases go through `pnpm run build` (webpack + electron-builder via `_scripts/build.mjs`).
`_scripts/build.mjs` handles desktop platforms only — it has nothing to do with the APK.

## Architecture

### Platform branching

Platform differences are resolved **at build time** by webpack `DefinePlugin`, not at runtime.
Each config in `_scripts/webpack.*.config.js` defines a different set of literals:

- `process.env.IS_ANDROID`
- `process.env.IS_ELECTRON` / `process.env.IS_ELECTRON_MAIN`
- `process.env.SUPPORTS_LOCAL_API` — true for Android and Electron, false for the PWA
- `process.env.IS_RELEASE`

These are substituted as constants, so `if (process.env.IS_ANDROID) { ... }` is dead-code
eliminated from the other bundles. This is why platform-specific imports inside such a branch are
safe. **When adding a platform branch, gate it on the capability flag (`SUPPORTS_LOCAL_API`) rather
than the platform where possible** — that is how the local-API code paths are already written.

There is one webpack config per target in `_scripts/`; a change to shared build behaviour usually
needs editing several of them.

### Android native bridge

The Kotlin side (`android/app/src/main/java/io/freetubeapp/freetube/`) injects a JS interface object
named `Android`. Webpack maps it to the importable module `android` via `externals: { android: 'Android' }`,
so renderer code does `import android from 'android'`.

Synchronous interface methods return directly. Async ones return an **id**, and the Kotlin side later
dispatches a `${id}-resolve` / `${id}-reject` window event; `awaitAsyncResult(id)` in
`src/renderer/helpers/android/jsinterface.js` wraps that into a promise. All of
`src/renderer/helpers/android/` follows this pattern (storage, dialogs, media session, PO tokens).

`src/renderer/helpers/android/nedb.js` backs the datastores on Android — `src/datastores/index.js`
picks the storage implementation per platform.

### Data backends

`src/renderer/helpers/api/local.js` (youtubei.js extractor) and `invidious.js` are the two backends,
selected by the `backendPreference` setting. State lives in Vuex modules under
`src/renderer/store/modules/`, persisted through `src/datastores/`.

`local.js` is where video info, deciphering, PO token generation, and SABR stream setup all come
together — it is the most platform-aware file in the renderer.

### Video player and SABR

`src/renderer/components/ft-shaka-video-player/` wraps shaka-player. YouTube's SABR protocol is
implemented in `src/renderer/helpers/player/`:

- `SabrSchemePlugin.js` registers a custom shaka `sabr:` networking scheme. `doRequest` drives the
  whole UMP request/retry loop and is the single place server directives (redirects, backoff
  policies, context updates, reload requests, PO token rejections) are handled.
- `SabrManifestParser.js` builds the shaka manifest from SABR stream info.

Two kinds of state coexist in `SabrSchemePlugin.js` and mixing them up causes real bugs:
`SabrStreamState` is **session-wide** (shared by the parallel audio and video requests), while
`CurrentState` is **per network request** and its counters reset on every segment fetch.

The `googlevideo` package ships a reference implementation of the same protocol in
`node_modules/googlevideo/dist/src/core/` (`SabrStream.js`, `SabrStreamingAdapter.js`). Consult it
when changing SABR behaviour — the plugin here is a hand-written port of that adapter, and
divergences from it have been the source of playback bugs.

When SABR gets stuck, the plugin emits a `reload` event that bubbles up as
`player-reload-requested` and is handled by `onPlayerReloadRequested` in `src/renderer/views/Watch/Watch.js`.
Note that `Watch.js` also reloads on `$route` changes, so a reload path that navigates must not also
call `reloadView()` itself.

## Committing

`lefthook.yml` installs a pre-commit hook that runs `pnpm exec eslint` on staged `.js`/`.vue` files
and `stylelint` on styles. Because pnpm is not on PATH here, the hook fails with
`sh: pnpm: command not found` unless a `pnpm` shim is on PATH for the `git commit` invocation.
Do not bypass it with `--no-verify`; put pnpm on PATH instead.

Note that in Git Bash, a Windows-style path (`C:/...`) cannot be prepended to `PATH` — the drive
colon is read as the separator. Use the POSIX form (`/c/...`).

## Localization

Strings live in `static/locales/`, with `en-US.yaml` as the source locale. Translations are
submitted through [Weblate](https://hosted.weblate.org/engage/free-tube/) rather than by PR, so new
strings normally mean editing `en-US.yaml` only.

`pnpm run checkforbadtemplates` compares every other locale's keys and interpolation placeholders
against `en-US.yaml` and writes the mismatches to `locale-errors.json`.
